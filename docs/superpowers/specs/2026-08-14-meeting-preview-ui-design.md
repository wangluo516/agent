# 会议确认预览展示设计

## 目标

修复网页端在接口返回 `needs_confirmation=true` 和 `meeting_draft` 时，只显示“请确认以下会议变更。”、不显示具体明细的问题。

用户仍通过输入“确认”或“取消”完成操作，本次不增加确认按钮，不修改后端 API，也不改变确认前禁止写入的安全约束。

## 方案

在 `app/static/app.js` 中增加一个纯格式化函数，把接口返回的 `meeting_draft` 转换为中文明细。收到响应后，前端继续展示 `body.reply`；若存在 `meeting_draft`，则在同一个助手消息气泡中追加明细和“请手动输入‘确认’或‘取消’。”提示。

只展示草稿中实际存在的字段：

- `title`：会议主题
- `start_at`：开始时间
- `end_at`：结束时间
- `attendee_ids`：参会人
- `room_id`：会议室
- `required_features`：所需设施

修改操作返回的 `MeetingPatch` 可能只有开始和结束时间，缺失字段不显示。创建操作返回完整 `MeetingDraft` 时显示全部可用字段。时间使用中文本地格式，内容仍通过 `textContent` 写入 DOM，避免 HTML 注入。

## 数据流与错误处理

1. 浏览器调用 `POST /api/chat`。
2. 前端读取 `reply`、`meeting_draft` 和 `needs_confirmation`。
3. 没有草稿时保持现有展示行为。
4. 有草稿时格式化明细并追加到回复文本。
5. 字段缺失或数组为空时跳过该行；时间解析失败时保留接口原值，不能阻断整条回复。

## 测试与验收

- 使用 Node 内置测试运行器直接测试纯格式化函数，无需新增 npm 依赖。
- 回归测试覆盖只有时间字段的修改草稿，以及包含主题、参会人、会议室和设施的创建草稿。
- 运行全量 Python 测试、Node 前端测试、Ruff 检查。
- 在真实运行页面复现“查询会议 → 改到下午 3 点”，确认页面显示开始和结束时间，同时不出现确认按钮。
