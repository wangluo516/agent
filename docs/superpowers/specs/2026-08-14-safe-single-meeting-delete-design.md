# 安全删除单个会议——设计说明

## 目标与范围

允许用户删除自己组织的一个明确会议，同时继续拒绝删除他人会议、删除所有人会议、清空会议和批量删除。删除必须经过“定位会议—展示完整预览—明确确认—按版本执行”，成功后返回被删除会议的完整信息。

本次采用物理删除，符合 24 小时面试题的最小范围。不增加恢复站、软删除字段、批量删除接口或管理员能力。

## 安全边界

LLM 只负责把自然语言解析为结构化 `delete` 意图和可选会议 ID，不能决定用户身份、权限、确认结果或数据库操作。最终安全检查全部由确定性代码执行：

- HTTP 边界提供当前用户，模型不能覆盖 `actor_id`；
- 一次只能解析和执行一个会议 ID；
- 只有会议组织者可以删除，参会者只有查询权限；
- “所有人、全部、批量、清空”等请求在 LLM 之前直接拒绝；
- SQL、任意 HTTP 和提示词注入仍由安全预检拒绝；
- 删除预览绑定用户、动作、会议 ID、会议版本和完整会议快照；
- 数据库只暴露按 `organizer_id + meeting_id + expected_version` 删除的方法，不提供按条件或批量删除方法。

把最终安全边界放在代码中可以抵抗模型误判、提示词注入和模型供应商行为变化。LLM 可以额外识别风险，但不能成为唯一的授权依据。

## 交互流程

1. 用户先查询会议，也可以直接说“删除我的设计评审”。
2. 解释器输出 `operation=delete` 和可选 `meeting_id`。
3. 工作流只在用户可见会议中定位目标：唯一结果可自动选择；多个结果要求用户按序号、唯一主题或会议 ID 选择。
4. 服务端读取最新会议，检查当前用户是否为组织者，并保存带版本号的删除快照。
5. 回复“请确认删除以下会议”，并通过现有 `meeting_draft` 字段展示主题、时间、参会人、会议室和设施。
6. 只有后续明确输入“确认”才执行；“取消”清除删除上下文且不写数据库。
7. 执行时仓库再次校验组织者和版本。成功后回复“会议已删除”，并展示刚删除的完整会议信息。

任何查询或新的独立操作都会使旧删除确认失效。会议不存在、已被修改或已删除时，返回“预览已过期，请重新预览”，不会删除其他会议。

## 组件修改

- 命令模型：为 `Operation` 和 `PendingAction.action` 增加 `delete`。
- Demo 解释器：识别“删除第一个”“删除我的某会议”等表达，并从当前候选中解析单个目标。
- LLM 解释器：在提示词中明确 `delete` 只表示删除意图，会议 ID 只能来自候选列表；身份和权限不得由模型生成。
- 安全策略：不再把所有“删除”一律拒绝，只拒绝批量、全量、清空、SQL 和越界指令；增加 `authorize_delete`。
- 工作流：增加删除目标解析、权限检查、预览、确认、过期校验和执行分支。
- 仓库：增加返回被删除 `Meeting` 的单记录版本化删除方法。
- 前端：复用现有会议详情渲染，无需新增按钮；删除预览和结果均由响应字段驱动。
- 文档：更新能力范围、安全说明和演示命令。

## 错误与状态处理

- 未找到会议：提示没有可删除的会议。
- 多个会议无法唯一定位：进入 `needs_clarification` 并展示候选序号。
- 参会者尝试删除：返回拒绝，不创建待确认动作。
- 批量或全量删除：在预检阶段返回拒绝，不调用 LLM、工具或数据库。
- 确认内容、用户、会议版本任一变化：确认失效。
- 重复确认或确认已删除会议：不删除其他记录，提示重新预览。

## 测试与验收

采用测试驱动实现，至少覆盖：

- 安全策略允许单会议删除表达，拒绝所有人、全部、批量、清空和 SQL 删除；
- Demo 与 LLM 解释器输出受限的 `delete` 意图；
- 查询多个会议后按序号删除；
- 直接删除唯一会议；
- 删除预览不写库，确认后只删除目标会议；
- 取消删除保持数据库不变；
- 参会者、错误会议 ID 和过期版本均不能删除；
- 删除成功响应包含被删除会议详情；
- 删除后日历忙闲查询不再把该会议计为忙碌；
- 现有创建、查询、更新、会议室推荐、安全拦截和真实 LLM 流程不回归。

完成标准为全量 pytest、Ruff、格式检查、compileall、前端测试通过，并使用正在运行的真实 LLM 服务手动验证“查询—删除第二个—确认—再次查询”的完整流程。
